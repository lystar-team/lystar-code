**LYStar Code Web 紧凑执行区方案**

日期：2026-10-02。范围：动态步骤与工具记录的呈现。交付：修订方案、可交互 HTML 参考、桌面与手机截图。产品源码未修改。

采用紧凑的黑白执行区。步骤、正文与工具类型图标共用左边缘；相邻工具栈中的文件和命令横向排布，保留对象名与点击入口。完整调用顺序留在执行记录中。

**输入框保留项**

保留现有 Composer、PromptInput、排队与附件区域、圆角与边框、阴影、尺寸、模型与思考强度、统计、发送与停止的位置及行为。执行区样式不能覆盖共享输入样式或布局变量。参考页只展示执行内容区，没有替代输入框。

依据：[输入组件](../../src/components/workbench/composer.tsx)、[输入区样式](../../src/styles.css#L192)、[现有设计规范](../../DESIGN.md#L211)。

**与现有呈现的区别**

| 对象 | 当前呈现 | 本版方案 |
| --- | --- | --- |
| 分段读取 | 展开的记录中，每次读取各占一行，同一路径重复出现 | 同一文件显示一次，例如 service.ts ×3；点击后查看三个行范围和各次状态 |
| 多个文件 | 文件记录纵向排布，常规视图包含长路径与行范围 | 文件名横向排布，空间不足时换行或使用 +N；完整路径与范围进入对象记录 |
| 层级 | 步骤、工具组、工具行的缩进叠加 | 主视图取消额外层级缩进，正文与类型图标共用左边缘 |
| 图标 | 已有 Lucide 工具与状态图标 | 沿用类型与状态图标，在横向对象旁显示运行和出错状态 |
| 输入框 | 项目现有编辑面板 | 原组件、外观、控件和交互保持 |

变化来自减少重复路径、调用行数与嵌套层级，文件和命令仍能在主视图识别。字号沿用现有量级。

**布局与密度**

- 桌面工具行高 28px，相邻活动行间距 0；正文间距沿用 12px。步骤标题下留 4px，步骤内容额外缩进为 0px。
- 类型图标 16px：读取 FileText、检索 Search、命令 Terminal、修改 Pencil、协作 Bot、技能 Sparkles。使用项目 Lucide，不加图标底座或彩色边框。
- 文件、命令保留等宽字体与 13px 量级。常规视图显示文件名，需要区分同名文件时补短目录。
- 正文保留“正文—工具活动—正文”的发生顺序。横向聚合限于同一个相邻工具栈，完整记录保留调用顺序。
- 移动端保留结构，对象换行；对象与溢出按钮的命中区域不小于 44px，行间不添加分组留白。完整路径换行，代码与终端输出在原有容器内滚动。

**真实功能边界**

`AgentStep` 在执行时创建，状态为 running、completed、failed、interrupted。标题、关联工具与消息、时间和可选摘要来自协议。界面在收到步骤后追加内容，不生成未来步骤、待办总数或完成百分比。[协议](../../../web-protocol/src/schemas.ts#L342)、[步骤控制器](../../../web-runtime/src/agent-steps.ts#L58)。

运行步骤沿用展开规则，用户的展开选择保留。没有 stepId 的调用留在原位置，不补造步骤标题。最终回复与已有「工作过程」入口保留。[步骤视图](../../src/components/workbench/conversation.tsx#L111)、[展开状态](../../src/components/workbench/use-conversation-expansion.ts#L15)。

文件对象按完整路径去重，不能合并不同目录的同名文件。×3 表示该对象的三次调用，各次范围和状态保留。运行、出错、取消与中断在主视图可发现；一次工具失败不能替步骤定性。溢出对象的运行和异常不能藏入 +N。正常历史对象可收敛，等待用户回复的入口保留。

点击文件对象查看该文件的调用记录；文件、Diff、图片和子会话沿用已有打开入口。未知工具保留其真实名称与状态，不推断含义。摘要只使用已有字段与解析能力。

**实施责任**

1. AgentStepContent：复用动态步骤，调整局部对齐、长标题和缩进。
2. ToolBatch、ToolActivityGroup：将相邻调用投影为横向对象，复用工具图标与内容入口，保留原记录。
3. useConversationExpansion：保留用户展开选择，核对工具数量增长后的呈现策略；沿用原滚动锚点与会话切换行为。

实施后核对步骤追加、工具数量增长、部分工具仍运行、失败/取消/中断、用户展开后继续更新，以及完成回合的最终正文。协议、Runtime、实际执行、输入区与其他工作区保留原有职责。
