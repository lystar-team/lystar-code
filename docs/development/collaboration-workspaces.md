# 协作工作区的创建、接收与回收

智能体身份和会话记录可以长期保留。工作区用于执行具体任务，成果接收后按状态回收。普通子会话和协作房间采用同一套生命周期。

## 选择执行模式

工作区模式由用户决定，不按任务类型强制选择。在 Web 的智能体配置中选择默认模式；房间任务可单次覆盖。优先级为本次选择、智能体配置、`direct`。已有任务继续使用原记录中的模式，不迁移或删除已有工作区。

| 模式 | 界面名称 | 文件访问 |
| --- | --- | --- |
| `direct`，未配置时的默认值 | 直接工作 | 在原项目目录执行，改动立即生效，不创建副本 |
| `shared` | 只读调查 | 使用原项目目录，任务要求只读查询，不修改文件 |
| `worktree` | Git 工作树 | 在独立工作树中执行，需要有提交记录的 Git 仓库 |
| `patch` | 项目副本 | 在项目副本中执行，保存交付补丁 |

`session_create` 和 `room_task_create` 均接受可选的 `workspaceMode`。未指定时沿用执行智能体配置；房间任务在执行时解析该配置。用户明确选择 `worktree` 而项目不满足条件时返回错误，不自动改为 `patch`。

智能体目录中的 `profile.json` 或 Markdown frontmatter 使用 `workspaceMode` 保存默认模式。普通 Web 会话创建采用异步原子写入，保存会话头并保持写锁，不在创建路径强制刷盘；成功保存后才创建执行 Runtime。

新 Git 工作区以主项目当时的文件内容作为基线，包含已经接收但尚未提交的成果。生成基线使用临时 Git 索引，不改变主项目的暂存区。交付只计算相对该基线的改动。

协作工具沿用当前角色的 `tools`、`excludeTools` 和全局工具设置。讨论、认领和执行回合使用同一套角色工具配置；角色只排除 `create_agent`、`session_create` 时，其他已配置工具继续可用，包括 Bash、Codemode、MCP 和扩展工具。显式传入的任务能力租约按其工具名单执行。

任务消息通过 `taskAction` 区分 `offer`（认领）和 `execute`（工作区执行）。认领成功后，Runtime 结束当前回合并启动执行会话。已被认领的任务不再投递认领通知，认领回合不自动生成答复，避免旧通知触发重复执行。执行会话调用 Room 工具时沿用负责成员的身份；恢复协作会话时读取当前角色工具配置。协作回合开始前启动扩展，使依赖初始化的工具可用。

## 接收成果

普通子会话完成后，先核对变更与验证结果，再调用 `session_accept_result`，或在协作列表选择“接收结果”。

房间任务成功交付后，结果自动投递给主会话。主会话核对产物与验证记录，调用 `room_task_update` 将任务标为 `done` 时接收改动并完成任务。需要返工时，先记录 `blocked` 和修改意见，再改为 `doing` 启动重做；执行会话沿用身份并读取意见。执行成员提交结果，主会话在用户已授权范围内决定接收与返工，只有需求取舍不明或超出授权时才交给用户决定。

看板展示待认领、进行中、阻塞和已完成。任务详情展示排版后的结果、任务内容、变更文件及进展评论，提供查看补丁与执行会话的入口；编辑和评论按需展开。成员提交成果后，任务保持进行中，直到主会话接收完成。

接收先核对调用者、任务状态和成功结果。`direct` 的改动已在原项目中，接收只确认结果，不复制或合并文件；`shared` 也不需要合并。隔离模式检查补丁能否完整应用，冲突时返回错误并保留工作区供修复。接收成功后任务标记完成，保留会话身份、历史、结果摘要和交付补丁。执行任务保持运行状态直到结果持久化与 Runtime 清理完成，再通知等待方，避免主会话在执行会话仍持有写锁时接收成果。

以下情况继续保留目录，并显示原因：任务正在执行、等待回复、仍有排队任务或协作消息、其他进程或客户端占用、成果尚未接收、任务失败，以及接收后再次产生改动。

已接收且没有上述占用的隔离工作区自动回收。`direct` 和 `shared` 使用原项目目录，无需回收，也不会删除原项目。已打开的隔离会话可在关闭后回收；Runtime 首次读取项目列表时，也会核对已接收的遗留工作区。批量回收通过“工作区管理”先预览，再选择具体项执行。

## 继续工作

回收不删除智能体成员、任务卡或会话。原会话收到新任务时，先按原模式准备工作区，再更新会话目录和工具访问范围。代码任务以当前主项目的成果为基线。

已接收但仍保留的工作区继续执行前，会更新交付基线，避免下一轮重复带回已接收的改动。房间任务重新开启时保留执行会话身份，并启动新一轮执行。

同一会话的接收、回收和新任务启动串行执行。回收时的会话写锁覆盖记录更新和目录移除；其他 Runtime 需要等待该操作完成后再恢复会话。

## 项目内信任继承

协作工作区默认沿用来源项目或上级目录中已有的信任决定，全局 `defaultProjectTrust: "always"` 同样生效。已信任项目派发协作任务时，无需再手动启用继承开关。项目信任设置可以关闭该项目的继承。

直接工作和只读调查使用来源项目的同一目录，自动沿用该目录的信任决定。Git 工作树继续核对父会话、同仓库关系、系统工作区登记和资源一致性；显式保存过资源授权指纹时，还核对该指纹。来源无法核验或资源不一致时，仍按原有流程确认。非 Git 项目副本继续按各自目录确认。来源项目明确不信任，或没有信任记录且全局选择 `never` 时，协作沿用不信任决定，不重复弹框。项目资源信任与工具操作权限分别判断。

协议通过 `collaborationInheritance` 返回 `enabled`、`inherited`、`sourceCwd` 和未继承时的 `reason`；设置请求使用可选参数 `inheritCollaboration`。

## 观察状态

项目会话列表返回工作区模式、状态、空间占用、信任来源和保留原因。状态变化发送 `sessions_changed`，界面刷新会话摘要。

| 状态 | 含义 |
| --- | --- |
| `active` | 正在使用工作区 |
| `delivered` | 结果已交付，等待接收 |
| `accepted` | 成果已接收，目录可能仍因占用而保留 |
| `failed` | 执行或交付未成功，保留用于恢复 |
| `released` | 目录已回收，会话仍可继续使用 |

浏览器使用现有 WebApi REST。Gateway 根据项目或会话确定所属目录：

- `POST /api/projects/:projectId/session-workspaces`：预览或回收选中的工作区。
- `POST /api/sessions/:sessionId/accept-result`：接收普通子会话成果。

日常处理以接收状态和实际占用为依据。时间长、会话显示完成或主会话结束，都不足以证明目录可以删除。来源不明的目录保留，检查其差异与独有提交后再决定。
