# 协作工作区的创建、接收与回收

智能体身份和会话记录可以长期保留。工作区用于执行具体任务，成果接收后按状态回收。普通子会话和协作房间采用同一套生命周期。

## 选择执行模式

| 任务 | 模式 | 文件访问 |
| --- | --- | --- |
| 调查、阅读、评审 | `shared`，默认值 | 共享项目目录，任务只开放读取工具 |
| Git 项目的代码写入 | 显式指定 `worktree` | 在独立工作树中执行 |
| 非 Git 项目的文件写入 | 显式指定 `patch` | 在项目副本中执行，保存交付补丁 |

`session_create` 和 `room_task_create` 均接受 `workspaceMode`。房间任务卡保存该选择，执行会话按它准备工作区。已有房间任务使用原记录中的模式。

新 Git 工作区以主项目当时的文件内容作为基线，包含已经接收但尚未提交的成果。生成基线使用临时 Git 索引，不改变主项目的暂存区。交付只计算相对该基线的改动。

## 接收成果

普通子会话完成后，先核对变更与验证结果，再调用 `session_accept_result`，或在协作列表选择“接收结果”。房间负责人沿用任务验收入口。

接收先检查补丁能否完整应用。冲突时返回错误，保留工作区供修复。接收成功后保留会话身份、历史、结果摘要和交付补丁。

以下情况继续保留目录，并显示原因：任务正在执行、等待回复、仍有排队任务或协作消息、其他进程或客户端占用、成果尚未接收、任务失败，以及接收后再次产生改动。

已接收且没有上述占用的工作区自动回收。已打开会话可在关闭后回收；Runtime 首次读取项目列表时，也会核对已接收的遗留工作区。批量回收通过“工作区管理”先预览，再选择具体项执行。

## 继续工作

回收不删除智能体成员、任务卡或会话。原会话收到新任务时，先按原模式准备工作区，再更新会话目录和工具访问范围。代码任务以当前主项目的成果为基线。

已接收但仍保留的工作区继续执行前，会更新交付基线，避免下一轮重复带回已接收的改动。房间任务重新开启时保留执行会话身份，并启动新一轮执行。

同一会话的接收、回收和新任务启动串行执行。回收时的会话写锁覆盖记录更新和目录移除；其他 Runtime 需要等待该操作完成后再恢复会话。

## 项目内信任继承

在项目信任设置中，可以启用或撤销“允许协作工作区继承信任”。该选择针对具体来源项目，默认关闭，不修改全局信任策略。

继承需要有效的来源项目授权、可核验的系统工作区登记，以及与已授权来源一致的项目资源。来源不明或资源发生变化时，仍需确认。当前继承仅支持 Git 项目；非 Git 项目副本继续按各自目录确认。项目资源信任与工具操作权限分别判断。

协议通过 `collaborationInheritance` 返回 `enabled`、`inherited`、`sourceCwd` 和未继承时的 `reason`；设置请求使用可选参数 `inheritCollaboration`。

## 观察状态

项目会话列表返回工作区模式、状态、空间占用、信任来源和保留原因。状态变化发送 `sessions_changed`，界面刷新会话摘要。

| 状态 | 含义 |
| --- | --- |
| `active` | 正在使用工作区 |
| `delivered` | 结果已交付，等待接收 |
| `accepted` | 成果已接收，目录可能仍因占用而保留 |
| `failed` | 执行或交付未成功，保留用于恢复 |
| `released` | 目录已回收，会话仍可继续使用 |

浏览器使用现有 WebApi REST。Gateway 根据项目或会话确定所属目录：

- `POST /api/projects/:projectId/session-workspaces`：预览或回收选中的工作区。
- `POST /api/sessions/:sessionId/accept-result`：接收普通子会话成果。

日常处理以接收状态和实际占用为依据。时间长、会话显示完成或主会话结束，都不足以证明目录可以删除。来源不明的目录保留，检查其差异与独有提交后再决定。
